Every account brings its own keys

Open Krida stores no video and holds no provider keys of its own. A Clerk sign-in makes an account, the account pastes a TMDB key and a debrid key, each profile installs Stremio addons, and three services move the rest: Convex syncs, Vercel serves public data, and the user's debrid service sends the picture.

  1. Sync runs on Convex. Clerk only says who signed in; picking a profile mints the session token every other call takes.
  2. Public data runs on Vercel, asked with the caller's own TMDB and MDBList keys, and cached for everyone.
  3. Play runs on Convex. It asks the profile's stream addons at once, ranks the answers, and plays through TorBox's HLS or straight from another service's file link.
  4. Every app shows krida-open.vercel.app, so a push to main reaches all of them. Only native code needs a release.

Read from the code at commit b40b95f, which is what /version.json serves live today (3 Nov 2026). References are file:line in ~/dev/krida-open.

Accounts wall off everything but parties

Account
One Clerk user: up to 8 profiles and one accountKeys row (convex/lib/accounts.ts:7-12).
Session
32 random bytes, stored as a SHA-256 hash, minted by profiles.choose (convex/profiles.ts:183-200). A token Clerk made is refused under a different Clerk user (convex/lib/auth.ts:60-63); callers with no Clerk identity, like /api, are trusted with the token alone.
PIN
4 digits, PBKDF2-SHA256 at 100,000 rounds with its own salt. Five wrong tries lock the profile for 5 minutes; setting a PIN signs out the profile's other devices (convex/lib/profiles.ts:6-39, profiles.ts:243-245).

No public function takes an account id. Each read finds the account from the session, so another account's data can't be named, let alone fetched.

Crossing accounts takes the link

Joining is allowed when one of these holds (convex/lib/rooms.ts:77-88): you were in it before, your account is the host's, you hold the link code, or you have an invite or an accepted knock. Kicked is out for good, link or not.

  • Invite in the app: only to your own account's profiles, or someone who was in it before (convex/invites.ts:21).
  • Party link: 16 random bytes, made by any member who isn't a guest (rooms.ts:917-931). Anyone signed in, of any account, joins with it.
  • Guest link: host only, one use, 24 hours, at most 8 per party; makes a temporary profile with no account and no keys (profiles.ts:23-87).

Everyone in a party watches the host's stream, found by the host's addons and played from the host's TorBox (convex/engine.ts:26-31). A link shared widely spends the host's TorBox.

The host hand-off rule

When the host leaves and others remain (convex/lib/rooms.ts:184-197):

  1. Take the remaining members by join time, leaving out guests and the kicked.
  2. Keep those whose account has a TorBox key TorBox still accepts.
  3. Pick the first one from the old host's account; failing that, the first of any account.
  4. Nobody left: the party ends for everyone.

The room's hostAccountId moves with the host, so after a hand-off to account B, A's other profiles need the link or an invite unless they were already in.

Check yourself: a hand-off across accounts

Profile A1 hosts on account A's TorBox. B1, from account B, joins by link; then A2, A's other profile, joins. A1 leaves. Who hosts? A2: step 3 prefers the old host's account, though B1 joined first. Had TorBox refused A's key since, B1 would host if B has TorBox, and otherwise the party would end.

Addons are Stremio links per profile

An addon is a base URL plus the manifest Convex fetched from it. Each profile keeps up to 50, in its own order, each on or off (convex/lib/addons.ts:11, convex/schema.ts:227-237).

Three ways to install

  • Paste a link: a manifest link, a stremio:// link or the bare base (shared/stremio.ts:42-57). Https only, no private hosts, and an addon that says it needs setup is refused with its configure page (addons.ts:63-89).
  • Stremio import: the browser signs in to api.strem.io and calls addonCollectionGet (src/features/settings/stremioImport.ts:8,32). Only the addon URLs reach Convex; the Stremio password never does (addons.ts:140-172).
  • Suggestions, built on the server from the account's debrid key: Torrentio as torrentio.strem.fun/{service}={key}, Comet with its settings as base64 JSON (shared/stremio.ts:189-211). TorBox's own addon isn't offered: stremio.torbox.app no longer resolves (stremio.ts:187), unlike what the spec says.

A profile can also copy another same-account profile's addons (addons.ts:233-254).

Play asks every stream addon at once

  1. The source list comes from enabled addons that list a stream resource, in the profile's order (convex/lib/addons.ts:50-56). Lists are kept 20 minutes per account, addon set and title (convex/sources.ts:15,136).
  2. Convex asks each addon whose manifest serves that type and id prefix, all in parallel: 20 s timeout, first 150 streams each. One failing addon costs only its own sources (providers.ts:63-108).
  3. Each stream is normalised: a [TB+] or [RD⚡] mark becomes a ⚡ cached mark, a bare info hash becomes a magnet link, YouTube and external links are dropped (shared/stremio.ts:234-257).
  4. Lists are joined in addon order, repeated URLs dropped, 300 kept (stremio.ts:260-270).
  5. Copies of one file (same cleaned file name, size within 1%) fold into one option with the cached copy first, then each option is scored (convex/lib/rank.ts:227-295).
  6. Up to 4 candidates are tried, 15 s each except the last (convex/engine.ts:41,54). TorBox: follow redirects to a torrent and file id, or add a cached hash, then createstream. Another service: follow the addon's redirect to the file, rejecting the "downloading" placeholder clips (providers.ts:140-375).

The score adds points for picture and subtracts for risk (convex/lib/rank.ts:175-221). For the browser:

score = R(res) + Q(quality) + 6 × min(bitrate, cap) / cap + 4 × (1 − position / options) − 20 if not cached − 25 buffer, − 6 slow, − 8 unknown − 10 upscaled, − 40 wrong episode − 14 HDR on SDR, + 3 HDR on HDR − 6 Dolby Vision only + 3 your audio, − 20 other audio + 2 your subtitles
The tables behind R, Q, cap and speed
  • R: 2160p 30, 1440p 27, 1080p 24, 720p 14, SD 4, unknown 12.
  • Q: Remux 8, BluRay 6, WEB-DL 5, WEB 4, WEBRip 3, HDRip 2, HDTV 1, DVD 0, CAM −30, unknown 2.
  • cap (Mbps): 2160p 30, 1440p 35, 1080p 40, 720p 15, SD 6; in the desktop app 4K's cap is 60.
  • Speed (rank.ts:100-113): in the browser a 4K file over 45 Mbps buffers and over 30 is slow, anything else over 90 buffers; with no bitrate, a 4K file over 40 GB buffers. In the app, over 60 Mbps or 60 GB buffers.
  • Language: the −20 applies only when the listing names languages and none is Multi, Dual Audio or Dubbed.
  • App (screen = "app"): HDR +4, Dolby Vision +2, lossless audio +3, and no HDR penalties, because mpv plays the original file.
Worked example: Chrome on an SDR laptop, audio English, 10 options after folding

Catalogs become Home rows

A catalog of type movie, series or anime that needs nothing but paging is a row (shared/stremio.ts:150-155), keyed addon:{manifestId}:{type}:{id} so a reinstall keeps its place (stremio.ts:163). The browser fetches the first page and shares it for 30 minutes; only IMDb and Kitsu ids are kept, since other ids have no title page (src/data/addons.ts:48-99).

When the browser can't read an addon (no CORS), it remembers the host and goes through /api/rows?addon=. The proxy allows only manifest, catalog, meta and subtitle paths, https, public hosts, 4 MB, signed in (server/addonProxy.ts:11-44, api/rows.ts:12-15).

The row editor sorts by one number (src/features/home/homeRows.ts:46-55):

score = ( 0.4 × fans + 0.3 × min(1, 2.2 × alike) + 0.2 × quality + 0.1 × popularity ) × fit − penalty

Default ranks put Continue watching at 10 and picks at 20; addon catalogs fill slots 35, 55, 70, 85, 95, 110, 115, 140, 150, 170, 180, 190, 200, then every 30 (homeRows.ts:7-41). Rename, hide, pin, the type suffix and the banner row are profile prefs (convex/schema.ts:31-36).

Picks are four signals times fit

The browser builds the taste from the profile's synced tables, sends it to POST /api/recs, and saves the rows it gets back (docs/recommendations.md). The server never reads anyone's history from Convex for this.

A title keeps its strongest signal, and the top 30 become seeds.

Scoring a candidate for Top picks

Candidates are Krida's built-in rows, well-voted titles in each language the profile watches, TMDB's recommendations for the top 20 seeds, and up to 150 titles from the profile's first 8 addon catalogs (server/recs.ts:136-167, src/features/home/recsRefresh.ts:15-16).

pinned rows: pin index moved rows: 100 + position other rows: 1100 + default rank
fans
Sum over seeds of weight × (1 − rank / 25) × trust, where rank is the title's place in TMDB's recommendations for that seed; then divided by the highest sum (server/recs.ts:170-189). Trust is 0.4 for titles voted under 6, and ×0.25 when a non-English seed points at another language, Indian languages counting as one (server/score.ts:110-114).
alike
Seed-weighted mean of 0.5 × genre Jaccard + 0.25 cast + 0.15 director + 0.1 writer overlap, each overlap min(1, shared / 2), and ×0.4 when one is animated and the other isn't (score.ts:42-51).
quality
(MDBList score − 50) / 40, else (IMDb rating − 5) / 4, else 0.45, kept in 0 to 1 (score.ts:68-74).
popularity
log(1 + TMDB popularity) over the pool's highest.
fit
language × era. Language is 0.3 + 0.7 × min(1, 1.5 × the seed weight in that title's world / the top world's); worlds are anime, Indian cinema, or the original language. Era is 1, or 1 − 0.03 per year older than (floor year − 3), at least 0.4, where 15% of seed weight is older than the floor year (server/recs.ts:81-109).
penalty
0.3 × the closest disliked title's similarity, when that's over 0.35 (recs.ts:196-200).

Titles rated under 6.5 never make Top picks (6 for other rows). The row keeps one title per franchise, skips franchises already watched, and is chosen by maximal marginal relevance: value = 0.75 × score − 0.25 × the highest genre overlap with what's picked, with each format capped near its share of seed weight (recs.ts:255-275, score.ts:85-104).

The other rows: Because you watched, For you and X, a new profile
  • Because you watched, up to 3 rows, loved seeds first: (0.5 × fans of that one seed + 0.3 × similarity + 0.2 × quality) × world × fit − penalty, where world is 1 in the seed's world, 0.45 outside it. A row needs 6 titles and is skipped when 40% repeats an earlier one (server/recs.ts:300-341).

When it runs, and whose keys it spends

The browser recomputes a minute after the taste changes (at least 2 minutes apart), when another profile's taste changes, and when picks are 6 hours old, checked every 30 minutes and 5 s after opening (recsRefresh.ts:27-35).

Each run spends the caller's TMDB key on recommendations for up to 20 seeds, language lookups and language rows, and up to 8 MDBList batches of 200 ids; Cinemeta and Kitsu need no key (server/recs.ts:140-153).

Everything lands in Vercel's runtime cache, shared by all users, so a title one person looked up costs the next person nothing (server/cache.ts:5-8).

Previews read keyframes from the file itself

/api/frames reads the film's MKV index out of the account's TorBox by file size, and /api/frame reads one keyframe, a few hundred KB of a file that can be 30 GB (api/frames.ts, api/frame.ts). The frames Worker does the same on Cloudflare, which doesn't bill bandwidth.

The Worker holds no TorBox key. /api/frames?ticket seals the caller's key with AES-GCM under SHA-256 of "krida frames ticket " + FRAMES_SECRET, with the file size and expiry as associated data, valid one day plus 5 minutes of clock skew (server/frameTicket.ts:15-66). It isn't deployed, so FRAMES_URL is unset and the player falls back to /api/frame at one picture every 90 s instead of every 10 s (docs/ops.md:57-66).
