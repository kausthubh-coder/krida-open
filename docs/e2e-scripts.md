# End-to-end scripts

The scripts in `scripts/` drive Chrome through playwright-core, or call Convex directly. They share
`scripts/lib/qa.ts`, which refuses a URL that isn't on this machine, a profile whose name has no `-QA-` part (use
names like `Regress-QA-one` or `Ratings-QA-x`) and, for scripts that call Convex, any backend but a local one or dev. A failed check or an uncaught page error ends the run
with exit code 1. Each script's header says what it checks, what it needs and how to run it; this page collects them.

## Keys per account

`node scripts/e2e-keys.ts` needs the QA app started with `npm run qa -- up --real` (no stand-ins, no seeded keys) and
TMDB, MDBList and TorBox keys in `.env.test.local`. Home and Search ask for a TMDB key, Connections turns down a wrong
key and saves the real ones, then Search, a title's ratings, Play and the timeline's pictures (Worker and `/api/frame`)
work on the account's keys, and clearing the TMDB key brings the notice back. Keys never reach a URL or the log.

## Where they point

- App: the first argument, else `KRIDA_URL`, else the QA app in `.qa/session.json`, else `http://localhost:$PORT`
  (5173).
- Profiles: names from the arguments, else the QA app's (`Regress-QA-one`, `Regress-QA-two`). Passwords come from the
  QA app, else `KRIDA_QA_PASSWORD`. Scripts sign in without Clerk: `signIn` in `scripts/lib/qa.ts` uses the app's `/qa`
  page and `convexSignIn` calls `profiles:qaSignIn`, which answer only on a local backend and dev
  (`convex/lib/deployment.ts`), never production. `signIn` returns once the page has left `/qa`: opening another page
  before then cancels the sign-in. Real Clerk sign-ins are `e2e-accounts`'s job.
- Convex, for scripts that call it: `CONVEX_URL` (and `CONVEX_SITE`), else the QA app's backend, else dev from
  `.env.local`. Only a local backend or dev.
- Screenshots go to `.artifacts/<name>` unless you pass a folder.

## What they need

- **QA app**: `npm run qa -- up` starts a throwaway local backend with two seeded profiles and a dev server. Catalog
  rows need `TMDB_API_KEY` and `MDBLIST_API_KEY` in `.env.local`. It has no TorBox, AIOStreams or Simkl keys, so
  nothing plays there. These scripts also run on dev with `*-QA-*` profiles, except `e2e-library`.
- **Dev**: a dev server on the dev backend and disposable `*-QA-*` profiles (`npx convex run profiles:add`), with
  `KRIDA_QA_PASSWORD`. Anything that plays a stream needs this. Remove the profiles afterwards.
- **Two browsers**: Chrome and Edge, one profile in each.

Gotchas:

- From Git Bash, set `MSYS_NO_PATHCONV=1` when passing `/title/...` paths.
- `npx convex logs` never exits; give it a timeout.
- The party scripts leave a party open if they stop halfway; the next run of `e2e-party-flow` leaves it first.

## The regression gate

`npm run regress` (`scripts/regress/`, steps in `.agents/skills/verify-krida/SKILL.md`) answers outside data from
`.artifacts/regress/network/`. What the store lacks it records once: `/api` through the first side's own local `/api`,
asking TMDB and MDBList with `TMDB_API_KEY` and `MDBLIST_API_KEY` (environment, `.env.test.local` or `.env.local`),
because the live site's `/api` answers only signed-in accounts. Delete the folder to record fresh data.
